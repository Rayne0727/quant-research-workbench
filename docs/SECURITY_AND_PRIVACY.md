# 安全与数据隐私说明

本说明描述当前代码边界，不代表项目已经接受专业安全审计，也不构成绝对安全保证。

## 1. 本地处理与云端处理

本地运行时，上传文件在用户电脑上的当前 Streamlit 应用进程中处理。部署到云端后，上传文件会传输到并在云端应用进程中处理。两者的数据位置、访问范围、平台日志和基础设施控制边界不同。

公开应用可能被任何能够访问地址的人使用；私人应用可减少访问范围，但访问控制不能替代数据脱敏、最小化和授权确认。

## 2. 当前应用处理的内容

应用只处理用户主动上传的受支持文件：通用预览支持 CSV/XLSX；现有业务分析支持标准日频收益 CSV、每周调仓净值 CSV，以及本应用导出的标准化比较 CSV。通用预览会在内存中读取选定文件或工作表的完整内容，用于限制检查和基础字段提示，页面只展示前 20 行；它不会自动映射字段或计算绩效。仅严格业务协议路径会继续字段验证、绩效计算、图表、确定性摘要和内存下载生成。

XLSX 使用只读取工作簿内容的依赖处理，不执行 Excel 宏，不加载外部链接内容，也不合并多个工作表。这些限制不代表文件内容经过安全审计，也不替代上传前的脱敏和授权检查。

当前应用没有数据库、用户账号系统、API Key、外部行情连接或自动交易功能。当前代码不会主动把上传文件永久写入 `data/`，也不会主动向外部 API 发送上传数据。

## 3. 边界与禁止上传内容

“不主动写入 data 目录”不等于绝对数据安全。操作系统、浏览器、托管平台、代理、监控和基础设施日志不由本项目代码完全控制。

请勿上传包含以下内容的文件：

- 账号、密码、API Key、访问 token 或 License 凭证；
- 券商、交易所或数据服务交易凭证；
- 个人身份、联系方式、财务信息等个人敏感信息；
- 未经授权的商业机密、客户数据或内部研究数据；
- 受合同、监管、版权或其他访问限制约束的内容。

上传研究数据前应先脱敏，并只保留分析所需的最少字段。即使使用私人仓库或私人应用，也应执行相同的数据最小化原则。

## 4. Git 与日志规则

- 原始用户数据不得进入 Git；`data/raw/*` 已被忽略，仅保留 `.gitkeep`。
- API Key、密码和其他凭证不得写入源码、配置、文档、测试或提交信息。
- 应用日志不得打印 DataFrame、CSV 行内容或完整上传数据。
- 调试日志可以记录异常类型和 traceback，但应避免包含用户数据和本地敏感路径。
- 浏览器下载内容由用户决定保存位置，不应复制回仓库提交。

## 5. 发现敏感信息已提交时

1. 立即停止 push、部署和进一步共享。
2. 将相关凭证视为已泄露，尽快吊销或轮换。
3. 识别受影响文件、提交和访问范围。
4. 不仅删除工作区文件；应由仓库负责人制定历史清理和协作通知方案。
5. 历史清理可能影响其他克隆和提交，应在明确授权及备份后执行。
6. 清理后重新扫描，并检查远程缓存、构建日志和已部署应用。

本项目的自动检查不会删除文件、重写历史或替用户轮换凭证。

## 6. 报告安全问题

在尚未建立公开仓库和正式安全渠道前，请直接联系项目所有者，提供最少必要的复现步骤、受影响版本和风险说明。不要在公开问题中粘贴真实凭证、用户数据或可直接利用的敏感内容。
