# Quant Research Workbench 用户指南

本指南面向没有编程基础的本地用户。当前版本为 `v0.1.0-rc1`，用于研究记录和结果核验，不构成投资建议。

## 1. 启动网站

1. 打开下载或克隆后的项目根目录。
2. 在文件夹空白处打开 PowerShell。
3. 执行：

   ```powershell
   .\scripts\run_app.bat
   ```

4. 终端显示本地地址后，在浏览器访问 <http://localhost:8501>。

启动脚本会先确认项目虚拟环境存在，并检查 8501 端口是否已被占用。终端窗口需要保持打开，因为网站实际运行在该终端中的 Python 进程里。

## 2. 停止网站

回到运行网站的终端，按 `Ctrl+C`。关闭浏览器标签页只会关闭页面，不会停止后台的 Streamlit 进程。

如果更新代码后看到“无法导入名称”，请完整停止旧进程，再重新运行启动脚本。仅刷新浏览器不能清除旧进程中的 Python 模块缓存。

## 3. 完成一次单实验分析

1. 在页面顶部选择“单实验分析”。
2. 没有文件时可保留“使用示例数据”，先确认指标、净值图和回撤图能够显示。
3. 分析已符合业务字段协议的文件时，选择“按现有标准协议上传”。
4. 明确选择文件格式，再上传一份不超过 20 MB、数据行数不超过 200000 行的 CSV。
5. 检查页面显示的数据模式、格式和主要计算字段。
6. 阅读核心指标、日期范围、图表、诊断和数据预览。
7. 按需填写实验名称、策略名称和研究备注。
8. 下载 Markdown 分析报告和标准化分析 CSV。下载内容在内存中生成。

页面中的“下载标准日频收益CSV模板”只演示字段和小数格式，不代表真实策略结果。模板中的 `benchmark_return` 可以删除。

## 4. 通用读取 CSV 或 XLSX

1. 在单实验页选择“通用文件导入（CSV/XLSX）”。
2. 上传一份 `.csv` 或 `.xlsx`；当前不支持 `.xls`、`.xlsm`、`.ods` 或其他格式。
3. CSV 可以使用自动识别，或手动选择逗号、制表符、分号、竖线。页面会显示实际编码和分隔符；支持 UTF-8 BOM、UTF-8 和 GB18030。
4. XLSX 只有一个工作表时会自动选择；有多个工作表时，必须由用户明确选择，切换后会重新读取预览。
5. 核对文件名、行列数、原始字段、基础告警和前 20 行预览。当前默认第一行为字段名。
6. 查看“字段识别建议”。页面会按固定规则展示建议字段、评分、置信度、主要理由和风险；展开“查看备选字段和字段画像”可以核对每个角色最多三个候选及只读画像。
7. 在“确认字段映射”中选择“策略收益率为主”或“策略净值为主”。收益率主口径必须选择日期和策略收益率；净值主口径必须选择日期和策略净值，其余角色可以不映射。
8. 核对每个下拉框中的原始字段名称、B.2 建议、阻断错误和风险提示。中低置信度候选不会自动预填；高置信度预填也不等于确认。
9. 勾选确认声明并点击“确认字段映射”。确认成功后只显示字段引用摘要，不会生成指标、图表、报告或下载。

候选建议只来自字段名和最多 `10000` 个非空观察值的固定数据画像，相同输入会得到相同结果；它不使用随机、机器学习、AI、联网服务或文件名语义。高置信度仍不等于字段已经确认，百分数单位提示也不会触发自动换算。

字段识别建议与字段映射确认是不同阶段。映射确认只保存在当前浏览器会话中，并与文件内容摘要、文件类型、CSV 编码和分隔符、Excel 工作表、第一行表头规则及有序字段列表绑定；文件或解析设置变化后必须重新确认，不会跨会话写入磁盘或数据库。

这条路径不会修改、重命名、转换或删除原始列，不会自动判断百分数单位，也不会计算绩效、绘图或生成报告和标准化导出。B.4 才会按照确认的映射进行标准化和严格数据验证。XLSX 读取不执行宏、不加载外部链接内容，也不会合并工作表。

## 5. 如何选择两种原始 CSV 格式

### 标准日频收益 CSV

当文件直接记录每日策略收益时选择。必需字段是 `date` 和 `strategy_return`，可选字段是 `benchmark_return`。收益率必须使用小数，例如 `0.01` 表示 `1%`。

### 每周调仓净值 CSV

当文件记录策略净值时选择。必需字段是 `date` 和 `nav_strat`，可选字段是 `daily_ret`。绩效以 `nav_strat` 为准，应用不会把 `daily_ret` 直接映射为策略收益。

选择错误格式时，页面会明确提示缺少字段，不会自动切换或猜测字段。

## 6. 导出标准化 CSV

单实验分析成功后，点击“下载标准化分析数据”。该文件统一包含日期、策略收益、标准化净值和回撤，是多实验比较唯一接受的输入格式。

标准化文件第一行净值为 `1`，第一行收益为空。请保留应用生成的字段名称，不要手工改成原始数据字段。

## 7. 完成一次多实验比较

1. 先在单实验模式逐份分析原始文件并导出标准化 CSV。
2. 切换到“多实验比较”。
3. 可以先使用固定比较示例检查页面。
4. 选择“上传标准化 CSV”，一次上传 2 至 6 份文件，每份不超过 20 MB 和 200000 行。
5. 确认实验名称、原始覆盖范围和共同日期范围。
6. 阅读共同区间指标表、净值图、回撤图和确定性摘要。
7. 下载比较指标 CSV、共同日期对齐净值 CSV 和 Markdown 比较报告。

多实验比较必须使用标准化 CSV，因为原始文件可能采用不同字段、净值起点和样本区间。标准化后才能用同一协议验证，并在所有实验真实共有的交易日期上重新计算。

## 8. 常见中文错误及解决方式

- “缺少必需字段”：核对所选格式和字段名，不要依赖自动映射。
- “date 包含无法识别的日期”：改为有效日期，并确认没有空值或重复日期。
- “收益与净值推导收益不一致”：不要手工修改标准化文件中的收益或净值列，重新从单实验模式导出。
- “文件大小超过允许上限”：减小源文件到 20 MB 以内；应用不会截断文件。
- “数据行数超过允许上限”：将单个文件控制在 200000 行以内；应用不会抽样。
- “无法识别CSV文本编码”：将文件另存为 UTF-8、UTF-8 BOM 或 GB18030。
- “XLSX文件无法读取”：确认文件是有效且未损坏的 `.xlsx`，不要仅修改扩展名。
- “至少需要上传 2 份”或“最多支持 6 份”：调整比较文件数量。
- “存在重复实验名称”：修改文件名，确保去除 `_standardized_data` 后的名称不同。
- “8501端口已被占用”：回到原终端按 `Ctrl+C`，不要同时启动多个实例。
- “应用处理过程中出现未预期错误”：记录操作步骤，完整重启应用后重试。

## 9. 数据是否会写入本地

本地运行时，上传内容在用户电脑上的当前应用进程中处理，应用不会主动把上传文件或下载结果永久写入 `data/`。浏览器下载由用户自行选择保存位置。`data/raw/` 中的本地验收数据被 Git 忽略，应用也不会修改它。

部署到云端后，上传内容会传输到云端应用进程中处理。请勿上传账号密码、API 密钥、交易凭证、个人敏感信息、商业机密或其他受限制内容；敏感研究数据应先脱敏。“不写入 data 目录”不是绝对安全保证，详细边界参见 [安全与数据隐私说明](SECURITY_AND_PRIVACY.md)。

## 10. 当前版本不能做什么

当前版本不支持实时行情、自动交易、交易明细分析、任意原始格式批量适配、未经用户确认的字段应用、通用文件标准化与绩效计算、跨实验基准比较、数据库、用户登录、AI 摘要、手动触发部署或投资建议。通用导入中的字段候选只是确定性规则建议，确认映射也只保存字段引用。
