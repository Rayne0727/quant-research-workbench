# Quant Research Workbench 数据协议

本文档对应 `v0.2.0`。标准协议字段名区分大小写；通用导入可以生成候选建议并由用户显式确认字段映射，但系统不会自动确认、重命名或修改字段。

## 1. 通用文件读取边界

通用导入支持 `.csv` 和 `.xlsx`，但读取成功、候选评分较高或字段映射已确认都不代表已符合下面的业务数据协议。该路径保留完整读取结果，报告原始字段名称、基础问题和前 20 行预览，生成确定性字段候选建议，再由用户选择策略主口径并显式确认原始字段引用；只有后续标准化预检、严格协议验证和最终确认全部完成后才进入绩效计算。

- CSV 编码仅限 UTF-8 BOM、UTF-8 和 GB18030；
- CSV 分隔符仅限逗号、制表符、分号和竖线，可自动识别或由用户手动选择；
- XLSX 只读取一个用户选定的工作表；单工作表时自动选择，多工作表时不猜测、不合并；
- 当前默认第一行为字段名，不自动定位其他表头行；
- 列名空格、重复、空名、`Unnamed`、全空列和混合类型只会被提示，不会被自动修复或删除。

候选角色限于 `date`、`strategy_return`、`strategy_nav`、`benchmark_return`、`benchmark_nav`、`drawdown` 和 `daily_ret`。名称匹配、数值或日期特征以及少量跨字段一致性核对均采用固定规则；每列最多分析 `10000` 个非空观察值。系统会显示评分、置信度、理由和风险，但不会因高置信度自动确认字段，也不会根据百分数单位警告转换数值。

候选识别与映射确认是两个阶段。仅当首选候选至少 `85` 分、为高置信度、没有相近候选或角色冲突、字段非空且未被其他角色预占时，页面才可以预填；预填仍不等于确认。用户必须明确选择策略收益率或策略净值主口径，解决字段重复使用和必需字段错误，勾选声明后提交。

确认结果只在当前会话中保存字段引用和风险提示，并绑定文件内容 SHA-256 摘要、文件类型、Excel 工作表、CSV 编码与分隔符、第一行表头规则和有序字段名称。任一来源或解析设置变化都会使旧确认失效。识别和确认均不会修改 DataFrame、重命名列、转换收益率单位、填补或删除数据；确认后可由用户主动进入标准化转换与数据质量预检，但确认映射本身仍不是绩效分析授权。

## 2. 标准化转换与数据质量预检

用户确认式字段映射生成的 `ConfirmedMapping` 只确认字段引用；标准化转换才依据该引用创建独立的新内存 DataFrame。原始 DataFrame、列名、索引、行数、行顺序和值保持不变，不使用 `inplace`，不排序、去重、填充、删行、截断、重采样、收益率单位换算或净值归一化。

两种候选结构固定为：

- 收益率主口径：`date`、`strategy_return`，以及仅在用户已映射时加入的 `benchmark_return`；
- 净值主口径：`date`、由已映射 `strategy_nav` 改名得到的 `nav_strat`，以及仅在用户已映射时加入的 `daily_ret`。

其他已映射字段只进入诊断预览。`benchmark_nav` 不推导 `benchmark_return`，`strategy_nav` 不推导或覆盖 `strategy_return`，`strategy_return` 不覆盖 `strategy_nav`，`drawdown` 不作为绩效输入。标准化预检可以在临时序列上做只读一致性比较，但不会把推导值写回任何 DataFrame。

日期白名单包括 pandas/Python 日期时间对象、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD` 和含明确时间部分的 ISO 格式。`01/02/2026` 等地区含义不明确的格式会阻断。时区值统一转换为 UTC 后移除时区标记，无时区值保持原墙上时间；系统同时提示该规则。缺失、无法解析、重复、同一自然日多条时间记录或非严格递增日期均阻断，且不会自动排序或聚合。

数值白名单包括整数、浮点数、`Decimal`、普通数值字符串及清理前后空格后的普通数值字符串。百分号、千分位、货币符号、万/亿/K/M、括号负数、中文数字和特殊占位符均不会静默转换。数值精度不主动四舍五入，`1` 保持为 `1`，不会解释为 `1%`。分析候选字段的缺失、不可转换、NaN 或无穷会阻断；诊断字段的相同问题只生成 warning。

`strategy_return` 和已映射的 `benchmark_return` 小于或等于 `-1` 时阻断；净值主口径的 `nav_strat` 非正、缺失、不可转换或有效观察不足 2 条时阻断。异常尺度、全正/全零、唯一值过少、净值常数或跳变等只提示用户核对定义和单位，不自动修复，也不声称原因一定来自费用、复权或录入错误。

映射标识使用固定角色顺序 `date`、`strategy_return`、`strategy_nav`、`benchmark_return`、`benchmark_nav`、`drawdown`、`daily_ret`，并包含主口径、来源标识、未映射空值和映射规则版本。标准化标识使用 SHA-256，包含 `source_key`、`mapping_key`、标准化策略版本、主口径和有序输出字段；不包含本地完整路径、原始数据行、上传字节、用户账号或凭证。任一来源、解析设置、字段顺序、映射、主口径或策略版本变化都会使旧预览失效。

预检通过只表示标准化数据质量检查没有发现阻断问题，不等于下面的严格协议已经验证，更不等于分析完成。标准化预检不调用标准 CSV 加载器、净值适配器、绩效、比较、报告、图表或导出流程。

## 3. 严格协议验证与绩效分析

通用导入设置两道显式门禁。第一道由用户点击“执行严格协议验证”，只接受与当前来源、映射和标准化策略绑定且 `is_preview_valid=True` 的标准化预检结果。收益率主口径把 `date`、`strategy_return` 和可选 `benchmark_return` 的内存副本交给现有标准日收益协议；净值主口径把 `date`、`nav_strat` 和可选 `daily_ret` 的内存副本交给现有净值适配器。桥接层不复制日期、数值、净值适配、收益复合或绩效公式，也不通过临时 CSV 重新读取。

严格验证结果展示协议名称、输入行数、有效分析观察数、日期范围、分析字段、基准存在状态、错误、warning 和净值适配器一致性摘要。严格验证成功只显示进入下一门禁的资格，不计算绩效、不生成报告或下载。

第二道门禁要求用户核对日期、收益率或净值字段定义与单位、主口径和分析范围，勾选最终声明并点击“开始绩效分析”。只有该点击事件才调用现有绩效、图表、摘要、Markdown 报告和标准化 CSV 导出流程。通用收益率路径与内容相同的标准日收益直接上传采用同一严格验证和计算函数；通用净值路径与内容相同的净值直接上传采用同一净值适配器、容差、诊断和计算函数。

收益率主口径下，已映射 `benchmark_return` 可以进入现有基准分析，未映射时按无基准处理。净值主口径当前不扩展基准支持：`benchmark_nav` 不推导 `benchmark_return`，诊断字段中的 `benchmark_return` 也不能绕过净值适配器。辅助 `strategy_return`、`strategy_nav`、`drawdown` 或 `daily_ret` 均不能覆盖用户确认的主口径。

`analysis_request_key` 使用 SHA-256，并包含 `standardization_key`、主口径、严格协议版本、净值适配器版本、桥接策略版本和有序分析输入字段。文件内容、CSV 编码或分隔符、Excel 工作表、字段顺序、确认映射、主口径、标准化结果或策略版本、严格协议版本、适配器版本或桥接版本变化时，旧严格验证和分析结果立即失效。

整个流程不自动除以 `100`，不修复、排序、去重、填充、删行或修改标准化结果，不创建新的基准净值适配逻辑，也不会在未最终确认或严格验证失败时继续计算。结果只保存在当前会话，不写入项目目录、数据库或第三方服务。

## 4. 标准日频收益 CSV

| 字段 | 类型 | 是否必需 | 定义 |
| --- | --- | --- | --- |
| `date` | 可转换为日期的文本 | 是 | 交易日期，不允许缺失或重复 |
| `strategy_return` | 有限数值 | 是 | 当日策略收益率，不能小于或等于 `-1` |
| `benchmark_return` | 有限数值 | 否 | 当日基准收益率 |

收益率使用小数格式：`0.01` 表示 `1%`，不能用 `1` 表示 `1%`。必需字段不得缺失；数据最终按日期升序排列，不删除问题记录。

单实验策略净值由 `(1 + strategy_return).cumprod()` 得到。存在基准时，基准净值由 `benchmark_return` 独立计算，并显示基准累计收益。

## 5. 每周调仓净值 CSV

| 字段 | 类型 | 是否必需 | 定义 |
| --- | --- | --- | --- |
| `date` | 可转换为日期的文本 | 是 | 净值观察日期，不允许缺失或重复 |
| `nav_strat` | 有限正数 | 是 | 策略原始净值，必须大于 `0` |
| `daily_ret` | 有限数值 | 否 | 文件原有的辅助收益字段 |

适配方式固定为：

```text
strategy_nav = nav_strat / nav_strat.iloc[0]
strategy_return = nav_strat.pct_change()
```

第一行保留为净值曲线起点，`strategy_nav` 为 `1`，但第一行没有前一净值，因此 `strategy_return` 为空且不计入有效收益日数。累计收益和回撤直接基于 `strategy_nav`；年化收益、波动率、夏普比率和盈利日占比基于后续非空收益。

`daily_ret` 只与净值推导收益进行一致性诊断，不用于重建净值，也不直接映射为 `strategy_return`。存在差异时，分析仍以 `nav_strat` 为准；应用不猜测差异属于何种成本口径。

## 6. 标准化分析 CSV

标准化文件由单实验模式导出，是多实验比较的输入。

必需字段：

| 字段 | 类型 | 第一行规则 |
| --- | --- | --- |
| `date` | 日期 | 净值起始日期 |
| `strategy_return` | 有限数值；第一行允许为空 | 第一行为空 |
| `strategy_nav` | 有限正数 | 第一行约等于 `1` |
| `drawdown` | 有限数值 | 与净值推导回撤一致 |

可选字段为 `benchmark_return` 和 `benchmark_nav`。标准化导出会把策略净值重新归一为 `1`，再重新计算收益和回撤。存在基准净值时也采用相同方式标准化基准字段。

一致性公式：

```text
strategy_return[1:] = strategy_nav.pct_change()[1:]
drawdown = strategy_nav / strategy_nav.cummax() - 1
```

## 7. 多实验比较输入协议

- 一次必须提供 2 至 6 份标准化分析 CSV。
- 每份文件必须独立通过标准化字段、日期、数值、收益和回撤一致性验证。
- 文件名去除扩展名及结尾 `_standardized_data` 后作为实验名称。
- 重复实验名称会停止整个比较，不覆盖任何文件。
- 可选基准字段允许保留，但当前不参与跨实验比较。

共同日期使用所有实验日期集合的交集：

```text
common_dates = dates_1 ∩ dates_2 ∩ ... ∩ dates_n
comparison_nav = common_strategy_nav / common_strategy_nav.iloc[0]
comparison_return = comparison_nav.pct_change()
comparison_drawdown = comparison_nav / comparison_nav.cummax() - 1
```

共同区间第一日收益为空，因为不能沿用共同区间开始前一日到当日的原始收益。共同日期不是简单的日历起止范围，系统不添加任一实验缺失的交易日期。

## 8. 不进行的处理

所有协议均不执行：

- 前向填充或后向填充；
- 插值；
- 收益缺失值填补；
- 问题行静默删除；
- 文件截断或静默抽样；
- 未经用户提交确认就自动应用、重命名或映射任意字段；
- 使用未来数据。

## 9. 资源限制

- 单实验上传文件最大 `20 MB`；
- 多实验每份文件最大 `20 MB`；
- 每份通用 CSV/XLSX 或标准 CSV 最多 `200000` 行；
- 通用导入最多 `500` 列；
- 多实验最多 `6` 份文件。

任一限制超出时，系统显示实际大小或行数及允许上限，并停止本次处理。

## 10. B.1a 可复现运行身份核心

B.1a 在内部库中定义 `qrw-run-manifest-v1` 单实验清单模型。该阶段只提供不可变模型、
确定性身份与 JSON 序列化能力，尚未接入 Streamlit 页面或下载按钮；用户可下载的 Manifest
属于 B.1b，研究包与多实验 Manifest 也不在本阶段范围内。

原始来源摘要使用上传文件的原始字节直接计算 SHA-256，保存为
`sha256:<64 lowercase hex>`。文件名、路径、修改时间、大小和操作系统元数据均不进入摘要。
Manifest 最多记录清理后的 basename 作为展示名称，不保留绝对路径，也不写入原始字节、
原始 CSV 行、session、浏览器或 UI 状态。

实际进入分析引擎的数据采用 `qrw-run-canonicalization-v1` 表示：列顺序由分析模式固定，
行顺序保持不变，DataFrame index 不参与，不排序、不去重、不填充、不插值。日期使用明确的
ISO-8601；有时区值统一转为 UTC `Z`，无时区值不按本机时区猜测。有限浮点数使用
`float.hex()`，正负零统一为正零；NaN 和正负无穷被拒绝。协议允许的缺失值统一为 JSON
`null`，其他缺失值被拒绝。进入身份的语义字符串使用 Unicode NFC，原始字节不做字符规范化。
规范化数据的 canonical JSON bytes 计算得到 `standardized_data_sha256`。

`qrw-analysis-identity-v1` 的 `analysis_id` 绑定规范化数据摘要、分析模式、固定消费列顺序、
`qrw-single-analysis-v1` 语义版本，以及真实影响结果的年化交易日数、无风险利率和波动率
自由度参数。相同规范化分析数据和分析语义产生相同 `analysis_id`。

`qrw-run-identity-v1` 的 `run_id` 在 `analysis_id` 之外绑定原始来源摘要、输入模式、文件解释、
映射及转换/验证协议 provenance。`direct_standard`、`generic_import` 和 `nav_adapter` 使用各自的
冻结 provenance 模型，避免无关的空字段。相同分析内容通过不同来源、映射或转换路径产生
不同 `run_id`。直接收益与通用收益在分析数据和语义相同时共享 `analysis_id`、但不共享
`run_id`；NAV 路径保留真实的不同分析模式与消费列语义，不强行与收益路径共享身份。

旧有 `source_key`、`mapping_key`、`standardization_key` 和 `analysis_request_key` 只作为可选
workflow traceability metadata 保存，不参与两个新身份。应用版本、可选 build revision、Python
及运行时依赖版本、数据摘要和 `generated_at_utc` 也只是信息字段，不进入身份；因此工程提交、
生成时间或环境变化不会改写研究身份。完整 Manifest JSON 使用 UTF-8、键排序、紧凑分隔符、
`ensure_ascii=False`、`allow_nan=False`，且不附加末尾换行。确定性文件名为
`qrw_run_<run_id 前 16 位十六进制>.json`。
