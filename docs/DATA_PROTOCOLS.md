# Quant Research Workbench 数据协议

本文档对应 `v0.1.0-rc1`。标准协议字段名区分大小写；通用导入可以生成候选建议并由用户显式确认字段映射，但系统不会自动确认、重命名或修改字段。

## 1. 通用文件读取边界

通用导入支持 `.csv` 和 `.xlsx`，但读取成功、候选评分较高或字段映射已确认都不代表已符合下面的业务数据协议。该路径保留完整读取结果，报告原始字段名称、基础问题和前 20 行预览，生成确定性字段候选建议，再由用户选择策略主口径并显式确认原始字段引用；不进入标准 CSV 加载器、净值适配器或绩效计算。

- CSV 编码仅限 UTF-8 BOM、UTF-8 和 GB18030；
- CSV 分隔符仅限逗号、制表符、分号和竖线，可自动识别或由用户手动选择；
- XLSX 只读取一个用户选定的工作表；单工作表时自动选择，多工作表时不猜测、不合并；
- 当前默认第一行为字段名，不自动定位其他表头行；
- 列名空格、重复、空名、`Unnamed`、全空列和混合类型只会被提示，不会被自动修复或删除。

候选角色限于 `date`、`strategy_return`、`strategy_nav`、`benchmark_return`、`benchmark_nav`、`drawdown` 和 `daily_ret`。名称匹配、数值或日期特征以及少量跨字段一致性核对均采用固定规则；每列最多分析 `10000` 个非空观察值。系统会显示评分、置信度、理由和风险，但不会因高置信度自动确认字段，也不会根据百分数单位警告转换数值。

候选识别与映射确认是两个阶段。仅当首选候选至少 `85` 分、为高置信度、没有相近候选或角色冲突、字段非空且未被其他角色预占时，页面才可以预填；预填仍不等于确认。用户必须明确选择策略收益率或策略净值主口径，解决字段重复使用和必需字段错误，勾选声明后提交。

确认结果只在当前会话中保存字段引用和风险提示，并绑定文件内容 SHA-256 摘要、文件类型、Excel 工作表、CSV 编码与分隔符、第一行表头规则和有序字段名称。任一来源或解析设置变化都会使旧确认失效。识别和确认均不会修改 DataFrame、重命名列、转换收益率单位、填补或删除数据；B.4 才会执行标准化和严格数据验证，当前不得将通用导入用于绩效结果。

## 2. 标准日频收益 CSV

| 字段 | 类型 | 是否必需 | 定义 |
| --- | --- | --- | --- |
| `date` | 可转换为日期的文本 | 是 | 交易日期，不允许缺失或重复 |
| `strategy_return` | 有限数值 | 是 | 当日策略收益率，不能小于或等于 `-1` |
| `benchmark_return` | 有限数值 | 否 | 当日基准收益率 |

收益率使用小数格式：`0.01` 表示 `1%`，不能用 `1` 表示 `1%`。必需字段不得缺失；数据最终按日期升序排列，不删除问题记录。

单实验策略净值由 `(1 + strategy_return).cumprod()` 得到。存在基准时，基准净值由 `benchmark_return` 独立计算，并显示基准累计收益。

## 3. 每周调仓净值 CSV

| 字段 | 类型 | 是否必需 | 定义 |
| --- | --- | --- | --- |
| `date` | 可转换为日期的文本 | 是 | 净值观察日期，不允许缺失或重复 |
| `nav_strat` | 有限正数 | 是 | 策略原始净值，必须大于 `0` |
| `daily_ret` | 有限数值 | 否 | 文件原有的辅助收益字段 |

适配方式固定为：

```text
strategy_nav = nav_strat / nav_strat.iloc[0]
strategy_return = nav_strat.pct_change()
```

第一行保留为净值曲线起点，`strategy_nav` 为 `1`，但第一行没有前一净值，因此 `strategy_return` 为空且不计入有效收益日数。累计收益和回撤直接基于 `strategy_nav`；年化收益、波动率、夏普比率和盈利日占比基于后续非空收益。

`daily_ret` 只与净值推导收益进行一致性诊断，不用于重建净值，也不直接映射为 `strategy_return`。存在差异时，分析仍以 `nav_strat` 为准；应用不猜测差异属于何种成本口径。

## 4. 标准化分析 CSV

标准化文件由单实验模式导出，是多实验比较的输入。

必需字段：

| 字段 | 类型 | 第一行规则 |
| --- | --- | --- |
| `date` | 日期 | 净值起始日期 |
| `strategy_return` | 有限数值；第一行允许为空 | 第一行为空 |
| `strategy_nav` | 有限正数 | 第一行约等于 `1` |
| `drawdown` | 有限数值 | 与净值推导回撤一致 |

可选字段为 `benchmark_return` 和 `benchmark_nav`。标准化导出会把策略净值重新归一为 `1`，再重新计算收益和回撤。存在基准净值时也采用相同方式标准化基准字段。

一致性公式：

```text
strategy_return[1:] = strategy_nav.pct_change()[1:]
drawdown = strategy_nav / strategy_nav.cummax() - 1
```

## 5. 多实验比较输入协议

- 一次必须提供 2 至 6 份标准化分析 CSV。
- 每份文件必须独立通过标准化字段、日期、数值、收益和回撤一致性验证。
- 文件名去除扩展名及结尾 `_standardized_data` 后作为实验名称。
- 重复实验名称会停止整个比较，不覆盖任何文件。
- 可选基准字段允许保留，但当前不参与跨实验比较。

共同日期使用所有实验日期集合的交集：

```text
common_dates = dates_1 ∩ dates_2 ∩ ... ∩ dates_n
comparison_nav = common_strategy_nav / common_strategy_nav.iloc[0]
comparison_return = comparison_nav.pct_change()
comparison_drawdown = comparison_nav / comparison_nav.cummax() - 1
```

共同区间第一日收益为空，因为不能沿用共同区间开始前一日到当日的原始收益。共同日期不是简单的日历起止范围，系统不添加任一实验缺失的交易日期。

## 6. 不进行的处理

所有协议均不执行：

- 前向填充或后向填充；
- 插值；
- 收益缺失值填补；
- 问题行静默删除；
- 文件截断或静默抽样；
- 未经用户提交确认就自动应用、重命名或映射任意字段；
- 使用未来数据。

## 7. 资源限制

- 单实验上传文件最大 `20 MB`；
- 多实验每份文件最大 `20 MB`；
- 每份通用 CSV/XLSX 或标准 CSV 最多 `200000` 行；
- 通用导入最多 `500` 列；
- 多实验最多 `6` 份文件。

任一限制超出时，系统显示实际大小或行数及允许上限，并停止本次处理。
